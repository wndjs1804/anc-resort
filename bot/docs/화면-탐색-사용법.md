# 화면 탐색 사용법 (디자인·레이아웃·UX 흐름 보기)

벤치마킹하고 싶은 웹사이트를 직접 돌아다니면, **무엇을 눌렀고 화면이 어떻게 바뀌었는지**를
스크린샷과 함께 시간순으로 기록해 주는 도구다. 기록을 Claude 에게 읽히면
"이 사이트는 이런 순서로 이렇게 보여 준다" 를 근거를 갖고 이야기할 수 있다.

데이터(API)를 보는 [explore.ts](../scripts/explore.ts) 와는 목적이 다르다.
이건 **화면** 을 본다.

## 쓰는 법

터미널에 그대로 붙여 넣는다. `<주소>` 만 바꾸면 된다.

```bash
cd /Users/song/Desktop/ace-resort/bot && npm run design -- --url=<주소>
```

예)
```bash
cd /Users/song/Desktop/ace-resort/bot && npm run design -- --url=https://www.example.com
```

모바일 화면(390×844)으로 보고 싶으면 뒤에 `--mobile` 을 붙인다.
```bash
cd /Users/song/Desktop/ace-resort/bot && npm run design -- --url=https://www.example.com --mobile
```

## 브라우저가 뜨면

1. **직접 돌아다닌다.** 로그인이 필요하면 직접 로그인한다. 도구는 아무것도 자동으로 누르지 않는다.
2. 누를 때마다 터미널에 `[0004] 클릭 — 예약하기` 처럼 한 줄씩 찍힌다. 스크린샷도 같이 찍힌다.
3. 중요한 지점에서는 **터미널에 설명을 적고 Enter**. 예: `여기가 날짜 고르는 화면`
   → 그 시점 전체 화면 스크린샷 + 메모가 기록에 남는다.
4. 다 봤으면 터미널에 `q` + Enter. (브라우저 창을 그냥 닫아도 된다.)

## 결과

`bot/docs/design-captures/<사이트이름>-<시각>/` 아래에 만들어진다.

| 파일 | 내용 |
|---|---|
| `report.md` | **이것만 보면 된다.** UX 흐름 표 → 디자인 값 → 화면별 스크린샷·골격 |
| `shots/` | 단계별 스크린샷 (2배 해상도) |
| `steps.ndjson` | 원자료. 보고서를 다시 만들 때 쓴다 |

`report.md` 에 들어 있는 것:

- **UX 흐름 요약** — 몇 초에 무엇을 눌렀고 어느 화면으로 갔는지 표 한 장
- **디자인 값** — 이 사이트가 실제로 쓴 색·글꼴·글자 크기·모서리 둥글기·여백을 **많이 쓴 순서로**.
  "글자 크기 단계가 4개구나", "강조색은 이 파랑 하나구나" 를 눈이 아니라 숫자로 확인할 수 있다.
- **화면 골격** — 화면이 어떤 덩어리로 나뉘고 각각 몇 px 인지, 가로 배치인지 세로인지, 몇 열 그리드인지

## Claude 에게 시킬 때

기록을 마친 뒤 이렇게 말하면 된다.

> `bot/docs/design-captures/<폴더이름>/report.md` 읽고,
> 이 사이트가 화면을 어떻게 구성했는지 정리해 줘.
> 우리 조회 화면에 가져올 만한 것 세 가지만 골라 줘.

## 지킬 것

- **읽기만 한다.** 남의 사이트에서 글쓰기·결제·신청 버튼은 누르지 않는다.
- 스크린샷에 **로그인한 내 정보가 찍힐 수 있다.** `docs/design-captures/` 는 커밋되지 않게 막아 뒀지만,
  파일을 남에게 보낼 때는 한 번 열어 보고 보낸다.
- 구조를 참고하는 것과 이미지·문구·소스를 그대로 가져오는 것은 다르다. 후자는 저작권 문제다.

## 안 될 때

`--debug` 를 붙이면 페이지 오류와 읽기 실패 이유가 터미널에 찍힌다.

```bash
cd /Users/song/Desktop/ace-resort/bot && npm run design -- --url=<주소> --debug
```
